# 0006. 공식 이미지는 이력을 남기는 SQL 함수로 내린다

- 날짜: 2026-11-02
- 관련: #218, ADR 0004, ADR 0005

## 상황

ADR 0005 는 공식 이미지를 URL 그대로 쓰는 대신, 권리자 요청이 오면 바로 내리기로 했다. 1.0 prod 에 이미지를 내보내기 전에 그 방법이 있어야 한다.
백오피스는 아직 목 데이터 뼈대이고 카탈로그 화면은 1.2 일정이다. 앱은 `gacha.image_link` 를 보여 주며, `gacha_items.image_link` 는 아직 화면에 쓰지 않는다. 그래서 `gacha_items` 만 비우면 이미지가 그대로 보인다.

## 선택지

| 선택지                 | 장점                                      | 단점                                                   |
| ---------------------- | ----------------------------------------- | ------------------------------------------------------ |
| SQL 문서만             | 스키마 변경이 없다                        | 범위 조건을 잘못 적기 쉽고 이전 URL 이 DB 에 안 남는다 |
| SQL 함수 + 이력 테이블 | 호출이 단순하고 사유 · 이전 URL 이 남는다 | 마이그레이션이 하나 늘어난다. 실행은 사람이 한다       |
| 백오피스 버튼          | 쓰기 가장 쉽다                            | 로그인 · DB 연결 · 배포를 앞당겨야 해 11/8 에 빠듯하다 |

## 결정

- `public.take_down_images(범위, id, 사유, 메모)` 로 내린다. 범위는 `gacha` · `anime` · `all` 이고, `gacha` 와 그 가챠의 `gacha_items` 를 함께 비운다.
- 이전 URL 과 사유는 `public.image_takedowns` 에 남긴다. 테이블과 함수 모두 anon · authenticated 권한을 회수해 앱에서 접근하지 못한다.
- prod SQL Editor 에서 실행한다. 절차는 [이미지 삭제 요청 대응](../image-takedown.md).
- 연락처는 팀 공용 메일 `anniversaryarchive@gmail.com` 으로, 스토어 등록 정보와 앱 설정 화면에 표시한다.
- 요청을 먼저 본 사람이 처리한다.

## 이유

- 지금 일정에서 바로 쓸 수 있고, 앱 빌드 없이 다음 조회부터 반영된다.
- 지운 URL 을 이력에서 되살릴 수 있고, 어떤 이미지를 왜 내렸는지 DB 에서 볼 수 있다.
- 시차가 있는 세 명이 일해서, 먼저 본 사람이 처리해야 대응이 늦어지지 않는다.

## 알아 둘 것

- 먼저 본 사람이 처리하는 방식은 서로 미루거나 겹칠 수 있다. 시작할 때 팀 채팅에 알린다.
- `legacy-60.sql` 을 다시 실행하면 내린 라인업 이미지가 돌아온다. JSON 도 같이 고친다 (절차 문서).
- `all` 은 출처를 가리지 않고 `image_link` 를 모두 비운다. 운영자가 직접 올린 이미지가 생기면(1.2) 범위를 다시 본다.
- 백오피스 카탈로그 화면이 생기면 이 함수를 부르는 버튼을 검토한다. 그때는 `requireAdmin()` 을 거친다 (ADR 0004).
