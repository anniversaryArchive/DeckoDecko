# ADR (Architecture Decision Record)

되돌리기 어렵거나 여러 사람에게 영향을 주는 기술 결정을 한 페이지로 남긴다. 나중에 "왜 이렇게 했지?"를 PR · 대화를 뒤지지 않고 여기서 찾는다.

## 언제 쓰나

- 라이브러리 · 도구를 고를 때 (예: 바텀 시트 라이브러리)
- 폴더 · 패키지 경계, 데이터 흐름처럼 구조를 정할 때
- 팀 규칙을 바꾸는 결정 (예: 환경변수 이름)

버그 수정, 한 화면 안에서 끝나는 구현 방식은 쓰지 않는다. PR 본문으로 충분하다.

## 형식

파일 이름은 `NNNN-주제.md` (예: `0001-bottom-sheet.md`). 아래 순서를 지킨다.

```markdown
# NNNN. 결정을 한 줄로

- 날짜: YYYY-MM-DD
- 관련: #이슈, #PR

## 상황

## 선택지

| 선택지 | 장점 | 단점 |
| ------ | ---- | ---- |

## 결정

## 이유

## 알아 둘 것
```

- **상황**: 왜 지금 정해야 하는지. 제약 조건.
- **선택지**: 실제로 검토한 것만. 고른 것은 결정에 적는다. 표가 여럿이면 고른 줄에 "(채택)"을 붙여도 좋다.
- **결정**: 무엇을 하기로 했는지. 그대로 따라 할 수 있게 구체적으로.
- **이유**: 다른 선택지 대신 이것을 고른 까닭.
- **알아 둘 것**: 주의할 점, 다시 검토할 조건. 없으면 뺀다.

## 번호

- 병합되는 순서가 아니라 PR 을 여는 순서로 다음 번호를 쓴다. 열려 있는 PR 의 ADR 번호도 확인한다.
- 그래도 겹치면 나중에 병합하는 쪽이 번호를 올린다.
- 번호는 다시 쓰지 않는다. 결정이 바뀌면 이전 ADR 을 지우지 않고, 새 ADR 을 만든 뒤 이전 ADR 맨 위에 `> 0007 로 대체됨` 처럼 적는다.
