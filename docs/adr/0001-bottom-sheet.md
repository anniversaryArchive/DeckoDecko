# 0001. 바텀 시트는 @gorhom/bottom-sheet 로

- 날짜: 2026-10-16
- 관련: #112

## 상황

아이템 추가 · 수정, 폴더 고르기처럼 시트를 쓰는 화면이 여럿이다.
시트 안에 입력창이 많아서, 키보드가 올라올 때 시트도 같이 올라가야 한다.
아래로 끌어서 닫는 동작도 시안에 있다 (손잡이 막대).

## 선택지

| 선택지                    | 장점                                                     | 단점                                                         |
| ------------------------- | -------------------------------------------------------- | ------------------------------------------------------------ |
| `@gorhom/bottom-sheet`    | 끌어서 닫기, 키보드 피하기, 내용 높이 맞추기가 들어 있다 | 의존성이 하나 늘어난다                                       |
| Reanimated 로 직접 만들기 | 의존성이 늘지 않는다                                     | 끌기 · 키보드 처리를 우리가 만들고 고쳐야 한다               |
| RN `Modal` + 애니메이션   | 가장 빠르다                                              | 끌어서 닫기가 없다. 나중에 바꾸면 쓰는 화면도 다시 봐야 한다 |

## 결정

`@gorhom/bottom-sheet` 5.2 를 쓴다. `@deckodecko/ui/native` 의 `BottomSheet` 가 감싸고, 화면은 이 라이브러리를 직접 import 하지 않는다.

## 이유

- 이미 설치된 Reanimated 4 · Gesture Handler 위에서 동작한다 (5.2.14 가 Reanimated 4 를 지원).
- 시트 안 입력창의 키보드 처리를 직접 만들 필요가 없다.
- `BottomSheet` 로 감싸 두었으므로 나중에 라이브러리를 바꿔도 화면 코드는 그대로다.

## 알아 둘 것

- 한 번도 열지 않은 시트에 `dismiss()` 를 부르면 그 뒤의 `present()` 가 무시된다. `BottomSheet` 가 열려 있을 때만 닫도록 처리해 두었다.
- 기기에서 "동작 줄이기"(손쉬운 사용)가 켜져 있으면 시트가 애니메이션 없이 바로 열리고 닫힌다. 라이브러리가 접근성 설정을 따르는 것이라 그대로 둔다.
